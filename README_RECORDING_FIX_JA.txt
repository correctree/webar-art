ARARART 0.12.1 — 録画の停止・保存画面への遷移を修正

【原因の切り分け】
前版0.12.0のソースでは、MediaRecorderの終了通知が返らない場合に「動画を準備中」で無制限に待つ構造がありました。また開始と停止を1つのボタンで切り替えていました。ユーザー端末で、停止操作が届かなかったのか、届いた後の終了処理で止まったのかは現時点では断定できません。

【適用】
1 ZIPを展開します。
2 GitHub correctree/webar-art の main のトップで Add file → Upload files。
3 中の ar.html、src、studio、tests をまとめてアップロードします。外側のフォルダー自体は入れません。
4 mainへコミットしGitHub Actionsの成功を確認。
5 iPhoneの体験URLを再読み込みし PLAYER 0.12.1 を確認します。必要なら、? があるURLには &v=0121、ないURLには ?v=0121 を末尾に追加。
GitHub Pagesの体験ページ向け更新です。作品の再公開・Renderの再デプロイは不要です。

【まず5秒で確認】
1 ARを開始し作品を表示します。
2 左上「動画を撮影」を押します。
3 独立した赤い「■ 停止して保存へ」ボタンが出ることを確認します。
4 約5秒後、その赤いボタンを押します。
5 「動画を準備中」の後にプレビューが開くか確認します。
6 カメラ背景とAR作品が両方映ることを確認し、「共有・写真へ保存」から保存操作へ進みます。
7 iPhone共有メニューで「ビデオを保存」が表示されたら選択し、写真アプリで確認してください。

【今回の変更】
・開始ボタンと停止ボタンを分離。録画中は開始ボタンを無効にし、赤い停止ボタンを表示。
・MediaRecorder.stop()後、最終データと終了通知が返ってからプレビューを生成。
・終了待ち10秒のタイムアウトを追加。完了しない場合は録画用のトラックを解放して操作可能に戻し、診断ボタンを表示。これは失敗した録画を正常な動画へ変換する処理ではありません。
・停止時の例外、遅れて届く古いイベント、新しい録画への古いデータの混入を処理。
・MP4は特定コーデック文字列より汎用video/mp4を優先。
・一定間隔の分割出力を指定せず、停止時に最終動画を受け取る方式へ変更。これが今回の症状の原因だったと断定するものではありません。
・映像取得の負荷を下げるため、最大辺720px・最大15fps・映像ビットレート目安2Mbps・最長30秒へ変更。従来どおり無音です。
・必要時に、録画形式・録画状態・フレーム数・停止要求・データ受信・終了等の診断JSONを保存可能。
・カメラ自体のトラックは録画モジュールから停止しません。

【進まない場合】
エラーが出たら「録画診断を保存」で ararart-recording-diagnostic.json を保存できます。このファイルにはブラウザーのUser-Agentと録画イベントを含みます。映像・音声・ログイン情報は含めません。
このJSONを共有すると、停止操作の未到達／終了イベントの未到達／空データ等を区別しやすくなります。

【検証と限界】
自動テスト125件成功、JavaScript構文確認成功。非同期の最終データ到着→終了、終了通知がない場合の回復、古いイベントの排除、停止例外、独立停止ボタンの状態等を検証。
MediaRecorder・DOMを模したテストを含み、iPhone上のエンコーダー・実カメラ・写真アプリ保存の成功を実証するものではありません。iPhone/Androidでの録画と実ビルドは未確認です。実ビルドはGitHub Actionsで確認してください。
