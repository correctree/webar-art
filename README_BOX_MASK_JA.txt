ARARART 0.10.0 — 箱型の立体マスク（GLB / WebM / Sprite）

【1 適用】
1. ZIPを展開します。
2. GitHub correctree/webar-art の main のトップで Add file → Upload files。
3. 中の ar.html、studio.html、studio フォルダー、tests フォルダーをまとめてアップロードします。外側のフォルダー自体は入れません。
4. mainへコミットし、GitHub Actionsのデプロイ成功を確認します。
5. Renderの ararart-studio サービスを開き Manual Deploy → Deploy latest commit。Liveになるまで待ちます。今回はStudio・サーバーの検証処理も更新されるので、この手順が必要です。
6. ダッシュボードからプロジェクトを開き STUDIO 0.10.0 を確認します。表示が古い場合は再読み込みしてください。
7. マスクを設定後にプロジェクトを保存し、「公開する」で公開版を更新します。
8. iPhoneで公開リンクを開き PLAYER 0.10.0 を確認します。古い表示なら ? があるURLには &v=0100、ないURLには ?v=0100 を追加します。

【2 マスクを作る】
1. 制作画面の作品一覧で対象作品を選択。
2. 右側「配置・表示」→「箱型マスク」で「この作品に箱型マスクを使う」をON。
3. 選択作品を囲む水色の箱が表示されます。初期状態では作品全体を囲むので、すぐには見た目が変わらないことがあります。
4. 「箱の幅・奥行・高さ XYZ」のどれかを小さくすると、その境界で作品が切り取られます。
5. 「箱をドラッグで編集」を押すと、既存の「移動／回転／サイズ」ツールで箱を編集できます。「作品を編集に戻る」で作品側に戻ります。数値入力も可能です。
6. 「箱を作品に合わせる」は現在の作品の外接範囲へ箱を合わせ、箱の回転を0へ戻します。
7. 「内側だけ表示／外側だけ表示」を切り替え可能です。
8. 同じシーン・同じマーカーの他作品へ適用する場合は「同じマーカーの作品へ設定をコピー」。対象作品の既存マスク設定は上書きされます。コピー後は独立した設定で、後の変更は連動しません。

【3 挙動】
・作品ごとに1個の箱を設定します。単独の共通マスクオブジェクトをシーン一覧に追加する版ではありません。
・箱は作品のアニメーションから独立し、所属マーカーまたは空間配置の共通基点に固定されます。
・マーカーARではマーカーの姿勢、空間配置では共通親の姿勢と全体倍率へ追従します。
・作品のアニメーションが箱の境界を通過すると部分的に表示・非表示になります。
・水色の枠は編集時の選択中だけ表示。Studio再生・AR体験では非表示。
・3形式の描画と影のクリッピングへ設定を接続。箱外の隠れた部分のタップは除外し、マスク有効作品には大まかな画面範囲によるタップ代替を使いません。Studio編集時は隠れた形状も選択できます。
・保存、制作ZIP、サーバー保存、公開scene.jsonに各作品のboxMaskフィールドを保持。新規素材や権限設定は不要。マスクなしの既存作品はそのまま利用できます。
・切断面は塞ぎません。これは表示領域を切り取る処理で、GLB形状や映像ファイル自体を書き換えません。

【4 確認手順】
まず既存プロジェクトを複製または制作ZIPでバックアップして試せます。
1. GLBの箱を作品の半分程度の幅にし、再生時に切り取りを確認。
2. WebMの箱の幅を縮め、既存の透過が維持されるか確認。
3. Spriteでも同様に確認。
4. 箱を移動・回転し、作品の一部だけが表示されるか確認。
5. 連続アクションの移動で作品が箱から出入りするか確認。
6. 保存→ダッシュボード→再度開く。マスク設定が保持されるか確認。
7. 公開→iPhoneで、3形式の切り取り、影、見える部分のタップ、隠れた部分のタップ除外を確認。
8. マーカーAR・空間配置それぞれで確認。
9. マスクOFFで作品全体が戻るか確認。

【5 実施した検証・限界】
自動テスト107件成功。変更したJavaScriptの構文確認成功。追加テストはマスク設定の検証、3形式の保存復元、描画・影材料への接続、動画用シェーダーへのクリッピング処理接続、親座標系への追従、隠れた部分のタップ除外を確認しています。描画経路テストはThree.js等を模したテスト用オブジェクトを使うもので、GPUによる描画テストではありません。
この環境では依存パッケージ取得がHTTP403で拒否され、npmの実ビルドとブラウザー／iPhoneでの描画検証は未実施です。GitHub Actionsのビルド結果と実機確認が必要です。既存の追跡安定化・目印配置UI・作品群サイズ調整は維持しています。
