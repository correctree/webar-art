# ARARART 0.8.2 — シーン開始・フェード・一時停止

## 1. Macに適用
編集データは制作ZIPへ保存してください。現在のStudioを起動しているターミナルでControl+C。
ZIPをDownloadsへ保存し、次を実行します。

```bash
unzip -o "$HOME/Downloads/ARARART-0.8.2-scene-actions.zip" -d "$HOME/Downloads"
bash "$HOME/Downloads/ARARART-0.8.2/APPLY.sh"
```

既存のMacリポジトリ $HOME/webar-art-0.1 へ適用します。旧ソースをバックアップし、依存導入・テスト・本番ビルド・配信ファイル検査を通してからGitHubへpushします。.git・.env・.studio-data・独自の公開素材は保持します。
起動後 http://localhost:8080/dashboard.html を開きます。

## 2. 現在の制作データを一覧へ登録
旧版のブラウザー自動保存は同じブラウザーのStudioに残っています。
「Studioを開く」→必要なら制作ZIPを復元→「保存・公開」→保存フォルダー選択→「プロジェクトを保存」。
「プロジェクト一覧へ」を押すと保存した作品がカードとして表示されます。
既存のサーバー保存は初回一覧表示時に登録されます。ZIPをDownloadsへ保存しただけでは一覧へ追加されません。

## 3. ダッシュボード
新規作成／最近保存したもの／すべて／フォルダー／ゴミ箱、検索、サムネイル一覧を用意。
カードの「開く」で保存版を編集します。名前変更、複製、ZIP保存、保存フォルダー変更、ゴミ箱への移動、復元に対応。
ゴミ箱は制作データを隠す操作です。公開ページの削除や永久削除は行いません。
Webフォルダーはプロジェクトを整理する分類です。PCのFinderのフォルダーとは別です。
一覧のカードは「保存済みプロジェクト」で、公開状態・QRはStudioの「保存・公開」で確認します。

## 4. PCの指定フォルダーへZIPを保存
ChromeまたはEdge等の対応ブラウザーで、Studio「保存・公開」→「PCの保存先フォルダーを選ぶ」→対象フォルダーの書込を許可。
以後「制作ZIPを保存」で選択先へ 体験ID-project.zip を書き込みます。同じ名前は最新版で置き換わります。旧版を残す場合はZIP名を変更するか別のフォルダーを指定してください。
選択先は同じPC・ブラウザーに記憶します。権限を再要求する場合があります。
「ZIPダウンロードに戻す」で通常のダウンロードへ戻ります。
非対応ブラウザーはZIPダウンロードを使用します。保存場所はブラウザーの設定で指定してください。

## 5. 他のPCから使うWeb Studio（初回のみ）
このZIPでサーバー用プログラムを用意しています。公開サーバーの開設・GitHub App設定は別途必要です。
既にRenderでARARARTの制作サーバーを使っている場合は、下記設定を確認してManual Deployします。
Shared Worldのサーバーとは別サービスです。

1. GitHub Actionsで今回の更新が成功したことを確認。
2. Render → New → Web Service → correctree/webar-art → Docker。
3. 永続保存のためPersistent Diskに対応するプランを選択。費用はRenderの作成画面で確認。
4. DiskのMount Pathを /var/data に設定。
5. Environmentに以下を設定。

| キー | 値 |
|---|---|
| APP_ORIGIN | https://今回のRenderサービスURL（末尾/なし） |
| DRAFT_DIR | /var/data/webar-drafts |
| GITHUB_OWNER | correctree |
| GITHUB_REPO | webar-art |
| GITHUB_BRANCH | main |
| GITHUB_ALLOWED_LOGINS | correctree |

6. Health Check Pathは /health。Auto DeployはOFF。作品公開のpushごとに制作サーバーが再起動しないようにします。
7. docs/GITHUB_CONNECTION_JA.mdの手順でGitHub Appを作り、Client IDとClient SecretをRenderの環境変数へ設定。Contents Read and write等の権限を設定し、webar-artへインストール。
8. Manual Deploy → Deploy latest commit。
9. https://今回のRenderサービスURL/dashboard.html を開き「GitHubでログイン」。
10. 同じアカウントで別のPCから同じURLへアクセスしてログインすれば、同じプロジェクト一覧を開けます。

render.yamlも同じ構成のBlueprintです。Starterプラン・1GBのDiskを指定しています。適用前にRenderの料金と設定を確認してください。
Diskなしのサーバーでは再デプロイ後の保存維持は保証できません。
トークンとClient Secretはブラウザーの作品データやGitHubへ入れません。

## 6. ローカルの作品をWeb Studioへ移す
MacのStudioで制作ZIPを保存→RenderのStudioでZIPを復元→「プロジェクトを保存」。
localhostの「local」保存とRenderのGitHubユーザー保存は別です。自動転送されません。
Web版は初回「プロジェクトを保存」以後、変更から約3秒で自動保存します。初回保存前はブラウザー自動保存だけです。
保存は公開版を変更しません。iPhoneの体験を更新するには「公開する」が必要です。
サーバー再起動／認証期限切れ時はログインし直してください。画面の保存失敗表示を確認し、必要ならZIPで保管します。
複数PCが同じプロジェクトを更新した場合、古い保存日時からの上書きを拒否します。一覧から開き直すか、制作ZIPとして別に保存してください。共同編集の同期ではありません。

## 7. 追跡の安定化を確認
「マーカー・シーン」の「追跡モード」は「安定重視」が初期値。「追従重視」は動きへの追従を強めます。
位置・角度・サイズを平滑化し、急な変化は約120ms継続するまで保留。一瞬の認識ロストは約120ms保持し、長いロストでは非表示。再認識時は約70msの安定待ちを入れます。単位は描画時刻で、端末性能により実時間の見え方は変わります。
影も同じ安定化済みの座標へ追従します。誤認識を完全に防ぐものではありません。
「公開する」で更新→GitHub Actions完了→iPhoneを再読み込み→PLAYER 0.8.2を確認。
カメラ静止時のぶれ、ゆっくり移動、マーカーを隠して戻す、2枚マーカー、影とタップ反応を確認してください。

## 9. 0.7.0の新機能
アプリ表示名はARARARTに変更。GitHubリポジトリ名、localhost URL、公開ページURL、既存プロジェクト名はそのままです。
Studio上部の「ダッシュボードへ」で、未保存の編集をサーバーへ保存して戻ります。保存に失敗した場合は画面に留まります。静的配信ではブラウザー保存を行います。
Studio内の「空のプロジェクトを作成」は削除。新規作成はダッシュボードへ統一しました。

### 連続アクション
「配置・反応」で作品を選択→「タップで連続アクション」→「連続アクションを使う」をON。
「追加するアクション」を選び「アクションを追加」。上へ／下へ／複製／削除で順序を編集します。1作品24アクションまで。
- 回転：X/Y/Z軸、角度（度）、所要時間、繰り返し回数、往復。
- 移動：XYZの相対移動量、所要時間、繰り返し回数、往復。軸は作品のローカル軸です。移動量は正規化した作品に対する値で、メートル指定ではありません。親の配置サイズ・回転の影響を受けます。
- サイズ：XYZ倍率。1=変更なし、2=2倍、0.5=半分。チェーンONで同じ倍率をXYZへ設定。倍率は開始時サイズを基準に各行で掛け合わせます。描画の倍率は0.001〜100へ制限します。
- 待つ：待ち時間。
- 音：登録した音素材、音量。先に「音素材を追加」から登録します。
- シーン切替：切替先。必ず最後に配置します。

所要時間は1回・往復時は片道の時間。繰り返しは1〜20回。
往復OFFの回転・移動・サイズは各回の結果を積み重ねます。往復ONではその行の開始状態へ戻ります。
前の行が完了してから次を開始します。上限時間は各行片道60秒です。
再タップ：最初から／再生中は無視／再生中なら停止。停止は現在の状態を保持し、次のタップで最初から始めます。
終了時：そのまま／元へ戻す。シーン切替時は新しいシーンの初期状態へ移ります。

連続モードONでは旧「動き」と旧タップのシーン切替は使用しません。動画・GLB再生と「タップ時の音」は併用できます。旧タップ音とアクション内の音が重ならないよう、不要な旧音は「音なし」にしてください。
「従来の動きを取り込む」は空のアクション一覧に回転／浮き上がる／大きくなるを取り込みます。旧設定自体は保持し、連続モードOFFで以前の動きに戻せます。

### 設定例：回転→移動→移動→拡大
1. 回転：Z、90度、1秒、1回、往復OFF。
2. 移動：X=0.3、Y=0、Z=0、1秒、1回、往復OFF。
3. 移動：X=0、Y=0、Z=0.2、1秒、1回、往復OFF。
4. サイズ：XYZ=1.5、0.5秒、1回、往復OFF。
再タップ「最初から」、終了時「そのまま」。
右の「再生／停止」でプレビューし、中央の作品をタップします。プレビュー停止で配置時の状態に戻します。シーン切替を含む確認はプレビューを使ってください。
プロジェクトを保存→同じ体験IDへ公開→iPhoneで再読み込み→PLAYER 0.8.2を確認。
AR開始時に連続アクション用Web Audioを解除し、遅延した音を再生します。実機で音のタイミングも確認してください。


## 10. 0.8.2：開始方法・フェード・停止

音量・接近トリガーは削除した状態です。作品ごとに「開始方法：タップ／シーン開始」を選びます。
シーン開始にした作品は手動タップでは発動しません。左の一覧は「シーン開始」と表示され、開始方法の変更は右の選択欄で行います。
従来の制作ZIPはそのまま読めます。開始方法が保存されていない作品は「タップ」のままです。

### シーン開始で自動実行する例
1. プロジェクトを開き、「配置・反応」で対象作品を選択。
2. 「連続アクション」の開始方法を「シーン開始」にする。
3. 「連続アクションを使う」をON。
4. 「出現」：待ち時間2秒、フェード時間1秒。
5. 「回転」：Z軸、90度、所要時間3秒。
6. 「停止」：所要時間2秒。
7. 「移動」：方向・移動量を指定、所要時間1秒。
8. 「消える」：待ち時間1秒、フェード時間1秒。
9. 終了時は「そのまま」から試す。
10. 「再生 / 停止」でプレビューする。自動で開始し、先頭の出現は非表示状態から始まる。
11. 保存・公開→QRからiPhoneで再読み込み→PLAYER 0.8.2を確認。
12. AR開始→マーカー認識→待ち時間後にフェード表示することを確認。

シーン開始の発動は、そのシーンに入るたびに1回です。マーカーの認識が途切れて再認識しても、同じシーン内では再発動しません。
別シーンから戻る／ARを再開始することで、初期状態から再実行します。複数マーカーの作品は各作品のマーカー認識後に開始します。
認識待ち中は作品の連続アクションを開始しません。従来のシーン自動切替タイマーはシーン開始から進みます。

### 消える／出現の時間
- 待ち時間：その行に到達してから、表示を変え始めるまでの時間。0〜60秒。
- フェード時間：徐々に消す／現す時間。0〜60秒、0なら瞬時に切替。
- 前の行が終わってから待ち時間を数えます。シーン開始からの絶対時刻ではありません。
- シーン開始で先頭が「出現」の場合は、最初に非表示となり、待ち時間後に現れます。
- 消えた作品はタップできません。タップ開始の列で再出現させるときは、同じ列に「待つ」→「出現」を設定してください。
- GLB、WebM、Spriteの表示不透明度へ反映します。配置で設定した不透明度を上限としてフェードします。

### 停止と待つの違い
「停止」は同じ作品のGLBアニメーション・動画・Spriteの時間進行と、カメラへの向き追従を一時停止します。
指定時間が終わると、元の再生状態を保って再開し、次の行へ進みます。再生OFFだった作品のクリップを強制再生する操作ではありません。
他の作品は停止しません。音素材の再生は継続します。
「待つ」は、作品のアニメーション・動画・Sprite・向き追従を継続しながら、次の行への進行を待ちます。
いずれも連続アクション内の有限時間の行であり、過去の回転行を並行して動かし続ける設定ではありません。
ARのマーカー喪失時「一時停止」は従来どおりアクションの時間も止めます。

タップで鳴らす音は従来の方式を維持。シーン開始で鳴らす音は「ARを開始」の操作で有効にしたWeb Audioを使います。
音が鳴らない場合は「音声をテスト」と音ONを確認し、ブラウザーの音量設定も確認してください。
終了時「元へ戻す」は変形・表示・フェードを初期状態に戻し、向き追従を解除します。
空間配置は今回の変更に含めていません。
